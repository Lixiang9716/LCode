# 资源管理 feature：多 agent 测试驱动 · 基线/终验同协议 · 分阶段可回退

## 测试协议（固定，前后两次同协议才可对比）
先写 `docs/perf-protocol.md`：每项测试的确切命令、样本任务提示词、采集字段（轮次/tokens/墙钟/成功）、输出格式。**基线轮与终验轮必须严格按同一协议执行。**

## Phase 0：基线（多 agent 并行，当前 b1f9dd4）
5 个并行子 agent，各司一维：
1. **性能 agent**：release 构建耗时×3、二进制大小、`lcode --help` 启动×5、nextest 全量时长、10MB read/write 延迟
2. **真实 E2E agent**（DeepSeek key）：4 个代表任务（纯对话 / 多轮文件修改 / web_search 检索 / bash 资源检查），记录成功/轮次/tokens/墙钟
3. **回归 agent**：457 全量 + clippy/fmt/style 门禁
4. **能力 agent**：现有工具面与 read/write 行为的单元级采样（作为功能基线）
5. **安全 agent**：现有权限面采样（allowed_dirs/hooks/审批行为现状）
主 agent 汇总 → 写 `docs/perf-baseline.md`（基线值表）。

## Phase A-E：实施（每阶段独立 commit + 单阶段门禁）
- A 工具面 7→5（删 list_dir/edit_file，write_file 加 replace）
- B URL 能力 + 权限（blocking reqwest/限额超时/主机策略/allowed_dirs/网络强制审批）
- C 信息过滤（敏感路径拒绝 + scrub_secrets + 二进制拦截；先验证 secrets_scanner 库 API，依赖过重 → 回退自研熵+regex 小集合）
- D 密钥卫生（secrecy::SecretString）
- E assets skill（include_str! 落盘不覆盖）+ README
每阶段跑：全量门禁 + 该阶段新增测试；阶段内发现问题即修再提交。

## Phase F：终验（同一 5 agent 电池，同协议重跑）
- 重新启动与 Phase 0 相同的 5 个并行子 agent，按 `docs/perf-protocol.md` 原协议执行
- 主 agent 逐项对比基线，按阈值判决：

| 指标 | 回退警戒线 |
|---|---|
| release 构建时长 / 二进制 / 测试套件 / 启动 | +20% / +30% / +25% / +10% |
| 无 URL 10MB read 延迟 | +20ms |
| 真实 E2E 失败数 / 平均轮次 | 新增失败即回退 / +30% |
| 能力/安全 agent 断言 | 任何基线功能回退即修 |

## 回退机制
- 任一维度超阈值 → `git revert` 对应阶段 commit（A-E 各自独立可回退），不牵连健康阶段
- 若多维度劣化 → 整体回退至 b1f9dd4，只保留修复类 commit
- 终验对比结果与判决追加进 `docs/perf-baseline.md`

## 验收
Phase F 判决通过 = 全维度在阈值内 + 457+新增测试全绿 + clippy 0 / fmt / style；conventional commit 分阶段推送。
