# Security Policy

## Reporting a Vulnerability

**Please do not publicly disclose security vulnerabilities** (no public
issues, pull requests, or forum posts). To report a security issue, use one
of the following channels:

### Option 1: GitHub Security Advisory (Preferred)

1. Go to the [LCode repository](https://github.com/Lixiang9716/LCode).
2. Navigate to **Security → Report a vulnerability**.
3. Fill out the advisory form with as much detail as possible:
   - A description of the vulnerability and its impact
   - Steps to reproduce (or a proof-of-concept)
   - Affected versions
   - Any suggested fixes, if known

### Option 2: Contact the Maintainer

Email the maintainer directly at the address listed on the
[GitHub profile](https://github.com/Lixiang9716).

## Response Times

We take security reports seriously. Expected response times:

| Stage                 | Expected time  |
|-----------------------|----------------|
| Initial acknowledgment | Within 48 hours |
| Status update         | Within 1 week   |

You will receive an acknowledgment of your report within **48 hours**, and
we will keep you updated on the status of the fix and any coordinated
disclosure timeline.

## Supported Versions

Security fixes are backported to the latest stable release. The following
versions are currently supported:

| Version | Supported          |
|---------|--------------------|
| Latest  | :white_check_mark: |
| Older   | :x:                |

We recommend always using the most recent release. If a vulnerability
requires an urgent fix, a patch release will be published for the latest
version as soon as possible.

## Disclosure Policy

Once a fix is released, we will disclose the vulnerability publicly (via a
GitHub Security Advisory, changelog entry, and/or release notes) and credit
the reporter unless they prefer to remain anonymous. We ask that reporters
allow us reasonable time to fix and release the patch before any public
disclosure.
